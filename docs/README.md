# Slime Garden: Developer Guide

Slime Garden is a Roblox experience where you plant slime seeds and watch them grow in real time, including while you're offline. You harvest them with random sizes and mutations, sell them, expand your garden and rebirth. Server-wide weather events add mutations. A seed shop restocks every 5 minutes, and the Slimepedia collection gives long-term goals.

This folder is the developer guide. Related docs:

- [`GAME_DESIGN.md`](GAME_DESIGN.md): concept, loop, economy and monetization design
- [`LAUNCH.md`](LAUNCH.md): store listing, launch checklist, 30-day roadmap, KPIs
- [`REVENUE.md`](REVENUE.md): how Robux becomes money, with honest example numbers
- [`STUDIO_TESTING.md`](STUDIO_TESTING.md): what to verify by hand in Studio before publishing

## 1. Open the game in Roblox Studio

### Option A: no tools needed
1. Download [`release/SlimeGarden.rbxlx`](../release/SlimeGarden.rbxlx).
2. Double-click it, or use **File → Open from File** in Roblox Studio.
3. Press **Play** (F5). The world builds itself when the server starts. Your garden is ready a second or two after you spawn.

Note that the snapshot in `release/` is regenerated by `scripts/build.sh`. If you edit the code with Rojo (Option B), rebuild it.

### Option B: live-sync with Rojo (recommended for development)
1. Install [Rokit](https://github.com/rojo-rbx/rokit), then run `rokit install` in this folder. This installs the exact tool versions from `rokit.toml`.
2. Install the Rojo plugin in Studio (`rojo plugin install`).
3. Run `rojo serve`, open an empty Baseplate in Studio and click **Connect** in the Rojo plugin.
4. Delete the default `Baseplate` part from Workspace. The game builds its own ground.

### Saving in Studio
- Studio cannot use DataStores until the place is **published** and **Game Settings → Security → Enable Studio Access to API Services** is on.
- Without that access the game prints a warning and uses **temporary in-memory saves**, so it stays fully playable. Live servers never fall back like this. If data can't load there, the player is kicked rather than given a blank profile.

### Studio QA panel
In Studio only, a small **STUDIO QA** panel appears bottom-left (+1B coins, rare seeds, ripen all, Starfall). Store items whose id is still `0` are granted directly in Studio, so you can test the whole flow before creating products. The server ignores all of this in live games, because `RunService:IsStudio()` is checked on the server.

## 2. Project structure

```
default.project.json   Rojo project (also sets Lighting/atmosphere)
src/shared/            → ReplicatedStorage.Shared (catalogs + pure logic)
  Config.luau          all tunables (plots, timers, bonuses, badges, sounds)
  Species.luau         11 slime species (price, grow time, value, stock odds)
  Mutations.luau       variants + weather mutations and their odds
  Weathers.luau        weather events
  Products.luau        Robux passes / products  ← paste your ids here
  Economy.luau         all value / cost / multiplier math (unit tested)
  Stock, Quests, DailyRewards, Format, Rng, SlimeBuilder, Net, Remotes, Signal, Types
src/server/            → ServerScriptService.Server (one Script, rest modules)
  init.server.luau     bootstrap: init() every system, then start()
  Data/                Schema (defaults/migrations/repair), Store adapter
  World/World.luau     builds the whole map from parts at startup
  Systems/             DataService, Sync, Monetization, Weather, Boosts,
                       Tutorial, Retention, Index, Plots, Garden, Shop,
                       Sell, Rebirth, Leaderboard, Analytics
  Util/                RateLimiter, Validate, Notify, Badges
src/client/            → StarterPlayerScripts.Client (one LocalScript)
  State.luau           client mirror of server state
  UI/                  Theme, Kit (UI helpers + scaling), Windows
  Controllers/         HUD, GardenView, Shop/Backpack/Store/Index/Rewards/
                       Rebirth windows, Tutorial, WeatherFX, Notifications,
                       Sounds, ChatTags, DevPanel (Studio only)
tests/                 Lune test harness, mocks, specs, place validator
scripts/check.sh       format + lint + strict type-check + tests + build
scripts/balance.luau   economy pacing simulator
```

Architecture rules the code follows:
- **The server is authoritative.** The client only renders state and sends requests. Every remote is rate-limited and validated: type, then range (including NaN/inf), then ownership, then distance. Prices and values come only from server catalogs.
- **Persistence.** Profiles are session-locked using `UpdateAsync` with retries. They autosave every 60 s, save on leave, and flush on `BindToClose`. A lost lock kicks the player instead of overwriting newer data. The schema is versioned with migrations and self-repairs corrupt fields.
- **Purchases.** Receipts are idempotent: the purchase id is recorded in the profile in the same step as the reward. `PurchaseGranted` is returned only after that save succeeds.

## 3. Configure before publishing

1. **Products** (`src/shared/Products.luau`). In the Creator Dashboard, create these and paste each id into the matching `id` field:

   | key | type | intended price |
   |---|---|---|
   | starter_pack | Game Pass | 49 R$ |
   | big_garden | Game Pass | 149 R$ |
   | sell_anywhere | Game Pass | 149 R$ |
   | vip | Game Pass | 199 R$ |
   | lucky | Game Pass | 249 R$ |
   | fast_grow | Game Pass | 299 R$ |
   | auto_harvest | Game Pass | 349 R$ |
   | double_coins | Game Pass | 399 R$ |
   | instant_grow | Developer Product | 29 R$ |
   | growth_potion | Developer Product | 39 R$ |
   | luck_potion | Developer Product | 39 R$ |
   | prism_seed | Developer Product | 99 R$ |
   | coins_small / medium / large / huge | Developer Product | 25 / 75 / 199 / 449 R$ |
   | weather_goorain | Developer Product | 79 R$ |
   | weather_starfall | Developer Product | 199 R$ |

   Prices are set on Roblox, not in code. The store shows the live price fetched from Roblox. Items left at id `0` show "not available yet" in live servers.
2. **Game Settings → Places → Max Players = 6.** This must equal `Config.Plots.Count`. A 7th player would be politely kicked because there's no free plot.
3. **Security:** enable *Studio Access to API Services* (for testing saves).
4. **Optional:** set `Config.GroupId` (+10% coins for group members), create badges and set `Config.Badges`, and replace `Config.Sounds` with Creator Store audio for richer sound.
5. **Maturity & Compliance questionnaire** in the Creator Dashboard. It's required before the experience can be public.

## 4. Run the checks

```bash
scripts/check.sh          # stylua, selene, luau-lsp strict types, Lune tests, rojo build, place validation
lune run tests/run.luau   # tests only (filter: lune run tests/run.luau Economy)
lune run scripts/balance.luau 240 7   # pacing simulation: minutes, seed
```

The test suite covers economy math, odds distributions, schema repair, and session locking (two simulated servers sharing one DataStore). It also covers receipt idempotency under save failures. Finally, it runs **end-to-end server simulations**: the real server systems and the real world builder on a virtual clock, which play the tutorial loop, weather, persistence with offline growth, rebirth, purchases and malicious remote calls.

What automated tests **cannot** cover (rendering, input on real devices, MarketplaceService prompts) is listed in [`STUDIO_TESTING.md`](STUDIO_TESTING.md).
